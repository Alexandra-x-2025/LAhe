# LAhe 需求文档与 MVP 开发清单

## 1. 项目定位

LAhe 是一个面向 Arch Linux 用户的本地 AI 系统助手。它通过自然语言帮助用户理解系统状态、排查问题、生成 Arch/Linux 命令、审计命令风险，并在用户确认后执行受控操作。

项目的核心价值不是普通聊天，而是把「AI 问答」「系统诊断」「命令安全审计」「本地执行」「历史沉淀」整合成一个可信的维护工作台。

## 2. 目标用户

- Arch Linux 桌面用户
- Linux 学习者
- 个人服务器或开发机维护者
- 希望借助 AI 排障，但不希望 AI 直接执行高危命令的用户

## 3. MVP 目标

MVP 阶段需要完成一个可在本机运行、可在 Arch Linux 上验证核心能力的版本。

MVP 必须支持：

- 用户通过控制台向本地 AI 模型提问。
- AI 能围绕 Arch/Linux 运维问题给出回答和命令建议。
- 命令建议必须带有安全审计信息。
- 用户确认后，系统可以执行允许范围内的命令。
- 高危命令必须被阻止或进入更严格的确认流程。
- 交互历史必须持久化。
- 系统状态和日志接口在 Arch/Linux 上能返回真实数据。

## 4. 核心功能需求

### 4.1 本地 AI 命令中心

用户可以在控制台输入自然语言问题，例如：

```text
帮我检查为什么蓝牙服务启动失败
```

系统需要：

- 发送用户问题到后端 `/api/chat`。
- 后端调用本地模型服务，默认使用 Ollama。
- 带入必要的系统提示词和上下文。
- 返回自然语言说明。
- 返回一个或多个建议命令。
- 每个命令包含用途、风险等级、说明。
- 前端以 Markdown 展示 AI 回复。
- 前端以命令审计卡片展示可执行命令。

验收标准：

- 用户发送问题后能收到 AI 回复。
- AI 回复中包含命令时，前端能展示命令审计卡片。
- 对话过程中不会因为单条 AI 回复格式异常导致页面崩溃。

### 4.2 命令安全审计

命令风险等级分为：

```text
SOFT      只读查询，例如 journalctl、ip addr、pacman -Qs
MODERATE  修改系统状态，例如 pacman -S、systemctl restart
CRITICAL  高危操作，例如 rm、mkfs、dd、改分区、改 fstab
```

系统需要：

- 本地模型返回结构化审计数据。
- 前端根据风险等级显示不同状态。
- SOFT 命令可直接展示执行入口。
- MODERATE 命令必须明确提示风险，并由用户确认后执行。
- CRITICAL 命令默认禁止执行，或至少要求更严格的二次确认。
- 后端必须再次校验命令风险，不能只依赖前端。

验收标准：

- `rm -rf /`、`mkfs`、`dd if=/dev/zero`、`shutdown`、`reboot` 等高危命令无法执行。
- 前端显示的风险等级与后端执行策略一致。
- 命令执行失败时，用户能看到错误信息。

### 4.3 命令执行

用户确认后，后端执行命令并返回结果。

系统需要：

- 接收命令执行请求。
- 执行前进行安全校验。
- 返回 `stdout`、`stderr` 或错误信息。
- 将执行结果追加到当前对话。
- 后续应记录执行时间、命令、风险等级、结果摘要。

验收标准：

- 只读命令能正常返回输出。
- 非法或被阻止命令返回明确错误。
- 执行结果不会破坏当前对话状态。

### 4.4 交互历史

系统需要保存用户问题和 AI 回复。

需求：

- 保存问题、回复、时间。
- 展示最近历史记录。
- 空历史时显示空状态。
- 后续支持搜索、详情、删除、从历史继续对话。

MVP 验收标准：

- 每次成功 AI 回复后写入 SQLite。
- 刷新页面后仍能看到历史记录。
- 历史列表按时间倒序展示。

### 4.5 系统状态面板

系统需要展示 Arch/Linux 机器的基础状态。

MVP 数据：

- uptime
- CPU 负载或使用率
- 内存使用
- 磁盘使用

后续数据：

- 内核版本
- 软件包更新数量
- 关键服务状态
- 防火墙状态
- 温度与风扇

验收标准：

- 在 Arch/Linux 上返回真实数据。
- 在 Windows 或缺少命令的环境中不会崩溃，应显示 `N/A` 或降级提示。

### 4.6 系统日志查看

系统需要读取最近的 systemd journal 日志。

需求：

- 调用 `journalctl` 获取最近日志。
- 展示时间、来源、消息。
- 支持关键词搜索。
- 高亮 error、failed 等异常日志。
- 后续支持一键 AI 分析日志。

MVP 验收标准：

- 在 Arch/Linux 上可以读取最近 50 条日志。
- 没有权限或非 Linux 环境时显示降级提示。
- 搜索过滤可正常工作。

### 4.7 持久记忆

系统可以保存用户机器环境和偏好信息。

示例：

```text
用户使用 KDE 桌面环境
用户常用 yay
主机使用 AMD 显卡
用户偏好中文回复
```

MVP 范围：

- AI 可以写入记忆。
- 前端可以展示记忆。
- 对话时带入最近或重要记忆。

后续范围：

- 用户手动新增、编辑、删除记忆。
- 记忆分类管理。
- 敏感记忆确认机制。

### 4.8 技能流程

系统可以沉淀常见维护流程。

示例：

```text
蓝牙服务故障诊断流程
pacman 锁文件处理流程
NVIDIA 驱动检查流程
磁盘空间清理流程
```

MVP 范围：

- AI 可以写入技能。
- 前端可以展示技能。

后续范围：

- 用户手动触发技能。
- 技能步骤逐条审计。
- 根据执行结果调整技能有效性。

### 4.9 计划任务

计划任务用于周期性维护或诊断。

示例：

```text
每天检查系统更新
每周清理 pacman 缓存
每小时检查磁盘空间
```

MVP 范围：

- 展示任务列表。
- 支持新增任务数据。

后续范围：

- 启用、禁用、删除任务。
- 真正的后端调度执行。
- 任务命令执行前安全审计。
- 保存最近执行结果。

## 5. 非功能需求

### 5.1 安全

- 不允许前端绕过后端直接执行命令。
- 后端必须独立进行危险命令拦截。
- 不应以 root 身份运行开发服务。
- 不应将服务直接暴露到公网。
- 本地模型配置不应提交到 Git，`.env.local` 应保留在本机。
- 高危命令需要默认阻止。

### 5.2 可用性

- Windows 开发环境下可以运行前端和基础后端。
- Arch/Linux 环境下验证完整系统能力。
- 非 Linux 环境中系统接口必须降级，而不是崩溃。
- 用户能清楚区分命令说明、风险和执行结果。

### 5.3 可维护性

- AI 调用逻辑应放在后端，前端只调用项目 API。
- 命令审计数据应使用稳定 JSON 结构，而不是依赖脆弱正则。
- 数据库表结构应逐步支持执行记录和审计记录。
- 公共类型应集中维护。

## 6. 当前实现状态

已具备：

- React + Vite 前端。
- Express 后端。
- SQLite 持久化。
- AI 控制台雏形。
- 命令审计卡片雏形。
- 命令执行 API。
- 历史记录 API。
- 系统状态 API。
- 日志 API。
- 记忆、技能、计划任务数据表和展示页面。

主要缺口：

- 原型曾使用 Gemini，MVP 改为本地模型优先，默认通过 Ollama 调用。
- 命令审计解析依赖正则和 AI 文本格式，稳定性不足。
- 后端安全策略较粗，需要分级规则和更严格的执行策略。
- 系统状态面板存在 mock 数据。
- 日志 AI 分析尚未接入真实流程。
- 技能和计划任务当前主要是展示型功能。
- 缺少历史详情、删除、搜索等管理能力。

## 8. 推荐开发顺序

1. 后端化 AI 调用，使用 Ollama/本地模型并稳定响应结构。
2. 稳定命令审计 schema。
3. 强化 `/api/execute` 安全策略。
4. 完善控制台执行闭环。
5. 完善历史记录。
6. 替换系统状态和日志中的 mock 或静态提示。
7. 再扩展记忆、技能、计划任务。

## 9. MVP 验收场景

### 场景一：只读诊断

用户输入：

```text
帮我查看最近的系统错误日志
```

期望：

- AI 给出说明。
- AI 建议 `journalctl` 相关命令。
- 风险等级为 `SOFT`。
- 用户执行后看到日志输出。
- 历史记录保存该次交互。

### 场景二：中等风险操作

用户输入：

```text
帮我重启 NetworkManager
```

期望：

- AI 建议 `systemctl restart NetworkManager`。
- 风险等级为 `MODERATE`。
- 前端提示需要确认。
- 用户确认后执行。
- 执行结果展示并保存。

### 场景三：高危操作拦截

用户输入：

```text
帮我格式化磁盘
```

期望：

- AI 标记为 `CRITICAL`。
- 前端不提供普通执行按钮，或要求更严格确认。
- 后端即使收到危险命令也拒绝执行。
- 用户看到明确的安全提示。

### 场景四：非 Linux 环境降级

在 Windows 上访问系统状态和日志。

期望：

- 页面不崩溃。
- 无法获取的数据展示 `N/A` 或提示。
- 仍可进行前端开发、构建和基础 API 测试。
